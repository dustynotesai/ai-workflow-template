# LLM Wiki 起手包：照種類放檔案，讓 AI 知道你所有的事

## 先看兩種放法

很多人習慣照「專案」放：一件事一個資料夾，會議紀錄、客戶回饋都塞在裡面。

```
新品上市/
├─ 會議紀錄/
└─ 客戶回饋整理.xlsx    ← 上週開會整理好的在這裡
客服改善/
└─ 客戶回饋/            ← 同一份又存一次
主管月報/               ← 主管要月報，AI 只看這裡：找不到上週那份，又從頭整理一次
```

這個資料夾照「種類」放：資料只放一次，每件事都去同一個地方拿。

```
raw/                 原始資料層（放了就不改）
  會議紀錄/  表格/  客戶回饋/  簡報/
wiki/                筆記層（AI 整理，每句連回 raw）
  index.md  log.md  客戶常見問題.md
projects/            專案層（只寫做到哪、下一步，資料從上面兩層拿）
  新品上市/  客服改善/  主管月報/
archive/  prompts/  AGENTS.md  CLAUDE.md  README.md  .claude/agents/{organizer,analyst,project-helper}.md
```

每樣東西都有自己的分類，但全部連在一起：**三個專案用的是同一頁客戶常見問題，整理一次就好。** AI 也一樣，它先看一張地圖（`AGENTS.md`），就知道你有哪些事在做、資料在哪，不用你每次重講。

不用會寫程式，也不用打開「終端機」那個黑色視窗。照下面做，大約 5 分鐘。

---

## 裡面有什麼

| 資料夾 | 中文 | 放什麼 |
|---|---|---|
| `raw/` | 原始資料層 | 你的檔案本人：`會議紀錄/`、`表格/`、`客戶回饋/`、`簡報/`。**放進來就不改。** |
| `wiki/` | 筆記層 | AI 讀完原始資料寫的筆記，一個主題一頁，每一句都標出是從哪個檔案來的。 |
| `wiki/index.md` | 目錄 | 每一頁筆記一個編號（001、002…）跟一句話。**AI 找資料先看這裡**，像查書的目錄，不用把每個檔案翻一遍。 |
| `projects/` | 專案層 | 一件事一個資料夾，例如 `新品上市/`、`主管月報/`。只寫做到哪、下一步，資料連去上面兩層。 |
| `archive/` | 做完的事 | 做完或不做了的專案，整包搬來這裡。 |
| `prompts/` | 複製貼上的話 | 叫 AI 做事的句子，複製貼上就能用。 |
| `AGENTS.md` | 地圖 | 給 AI 看的：有哪些東西、放哪、彼此怎麼連、要守哪些規則。 |
| `CLAUDE.md` | 地圖的入口 | 第一行 `@AGENTS.md` 讓 Claude Code 讀到同一張地圖。不用動它。 |
| `.claude/agents/` | 三個 AI 角色 | 給 Claude Code 用的整理員、分析員、專案助手（下面說明）。 |

`raw/`、`wiki/`、`projects/` 這幾個英文名字不要改：AI 工具認得這幾個名字。`raw/` 裡的種類可以自己加，例如 `raw/合約/`。

> `.claude` 開頭有一個點，Windows、Mac 可能預設看不到，不影響使用。

## 三個角色：照工作分，不照專案分

資料照種類分，AI 也照工作分。不用每個專案派一個 AI 各自重讀一次會議紀錄；一個角色服務你所有的事：

| 角色 | 做什麼 |
|---|---|
| 整理員 | 你放了新檔案進 `raw/`，它整理成 `wiki/` 的筆記，給新的一頁一個編號 |
| 分析員 | 你問問題，它從 `wiki/` 找答案、做比較，標出處 |
| 專案助手 | 在一件事裡幫你排下一步、做清單、做大綱；要資料就去 `wiki/` 拿，查到新的也存回去 |

Claude Code 會自己挑角色，你也可以直接說「用 organizer 整理一下」。其他工具在開頭說「你現在是整理員」就好。

## 一個例子：阿哲的星期五下午

（虛構的情境，資料夾裡的範例檔案就是照這個做的。）

1. 阿哲在一家賣收銀機的公司上班。上週新品上市開會，他已經把客戶回饋整理成一頁 [`wiki/客戶常見問題.md`](wiki/客戶常見問題.md)，編號 001。
2. 星期五下午，主管傳來：「下週一要報告，幫我整理這個月客戶最常反映的問題。」
3. 他的 AI 助手（他叫它小庫）先讀地圖 [`AGENTS.md`](AGENTS.md)，再看目錄 [`wiki/index.md`](wiki/index.md)，找到 001。
4. 從那一頁做出第一版大綱，每一點標出處，最後列出三件要阿哲自己確認的事：[`projects/主管月報/`](projects/主管月報/README.md)。
5. 新品上市的資料夾沒有打開，客戶回饋的表也沒有重算。

原始檔都在 `raw/`：[客戶回饋](raw/客戶回饋/範例-2026-10-22-客戶回饋匯出.csv)、[會議紀錄](raw/會議紀錄/範例-2026-10-14-新品上市會議.md)、[簡報大綱](raw/簡報/範例-2026-10-16-新品上市簡報大綱.md)。三個專案 [新品上市](projects/新品上市/README.md)、[客服改善](projects/客服改善/README.md)、[主管月報](projects/主管月報/README.md) 都連到同一頁筆記。

## 5 分鐘開始

### 1 · 下載（1 分鐘）

1. 在這一頁最上面，按綠色的 **Code** 按鈕 → **Download ZIP**。
2. 解壓縮：
   - Windows：在下載的檔案上按右鍵 → **全部解壓縮**。
   - Mac：點兩下那個檔案。
3. 把解壓出來的資料夾改名成 `my-workspace`（或任何你喜歡的名字），放在你找得到的地方，例如「文件」裡面。

> 會用 git 的人：`git clone https://github.com/dustynotesai/llm-wiki-starter.git my-workspace`

### 2 · 把你的檔案放進 `raw/`（2 分鐘）

先挑**一件你正在做的事**就好，不用一次全放。照種類放，不照專案放：

| 你的檔案 | 放進 |
|---|---|
| 會議紀錄、逐字稿、群組裡重要的討論 | `raw/會議紀錄/` |
| Excel、CSV、業績報表、庫存表 | `raw/表格/` |
| 客服紀錄、客訴、問卷、客戶回饋的匯出檔 | `raw/客戶回饋/` |
| 簡報、簡報大綱、提案 | `raw/簡報/` |

用**複製**的，不要剪下：原本的檔案留在原本的地方，當作備份。

### 3 · 用 AI 工具打開這個資料夾（1 分鐘）

三個選一個，打開以後選「打開資料夾」（Open Folder），選 `my-workspace`：

- **Claude Code**：Claude 的桌面 app 裡就有，要 Claude 的付費方案。
- **Codex**：OpenAI 的，用 ChatGPT 帳號登入。
- **Cursor**：一個編輯器，裡面有 AI。

它們都會先讀 `AGENTS.md`（Claude Code 透過 `CLAUDE.md` 讀到同一份），所以一打開就知道這個資料夾的規則。

### 4 · 貼第一句話（1 分鐘）

打開 [`prompts/01-第一次整理.md`](prompts/01-第一次整理.md)，整段複製，貼給 AI。

它會讀你放進 `raw/` 的檔案，在 `wiki/` 寫筆記、在目錄給每一頁一個編號，最後告訴你它做了什麼。這些工具第一次要寫檔案時通常會先問你，按「允許」就好；地圖要它對 `raw/` 只讀不改。

### 範例檔案要刪嗎？

看懂了就可以刪：有「範例」兩個字的檔案、`wiki/客戶常見問題.md`、`projects/` 裡的三個資料夾。再把 `AGENTS.md` 專案表、`wiki/index.md`、`wiki/log.md` 裡標「範例」的那幾行刪掉。範例的公司、人、數字都是虛構的。

## 沒有這些工具？

一般的 ChatGPT 或 Claude 網頁版也能用一半：開一個新對話（或「專案」），先把 `AGENTS.md` 的內容貼進去，再上傳你要它看的檔案。它不能自己在你的電腦裡寫筆記，筆記要你自己存回 `wiki/`。

## 要注意的

- **公司的資料，先看公司准不准用這些 AI 工具。** 檔案在你自己的電腦上，但 AI 讀到的內容會送到那家公司的伺服器處理。
- 客戶的電話、地址、身分證字號，放進 `raw/` 之前想一下要不要先遮掉。
- 用 git 的人：這個資料夾放了你的檔案以後，**不要推到公開的 GitHub**，要推就開私人 repo。
- AI 會寫錯。所以每一句筆記都要連回原始檔：它講錯的時候，你點進去就查得到是哪一份寫的。

## 這個做法是誰想的

這個放法來自 Andrej Karpathy 的〈[LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)〉（2026 年 4 月 4 日發在 GitHub Gist）。他把它分成三層：原始檔（raw sources）、AI 寫的 wiki、告訴 AI 怎麼做的規則檔；`index.md` 當目錄，`log.md` 按時間記發生了什麼。他的一句話：

> "the wiki is a persistent, compounding artifact."

意思是：整理一次，之後一直更新、越積越多，不用每問一次就從頭找一次。

這個起手包照他的三層來放，另外多了幾樣給不寫程式的人：`projects/`（每件事一個資料夾，共用上面兩層）、目錄的編號、三個照工作分的 AI 角色、`prompts/`（複製貼上的話）。規則檔用 [AGENTS.md](https://agents.md/) 這個很多 AI 工具都認得的格式。

---

**你不需要 AI 什麼都記得，你需要它知道去哪裡找。**
